# 口播剪辑（通用）

有人对着镜头录了一段话，这个 skill 把它剪成一条能发的竖屏短视频。

核心思路分两层：
- **规则层**：这句话在说什么（观点 / 吐槽 / 数据 / 资料 / 细节 / 情绪高点 / 列举）→ 该用哪类画面。
- **模板层**：每个模板是一套分好层的画面（背景 / 原画面 / 人后文字 / 抠出的人像 / 人前元素），把人像放进去就出画面。换颜色和字体（皮肤）就是另一种风格。

**风格包是入口。** 一条视频先选一个风格包（`../../library/packs/<id>/`），字体、颜色、字幕样式、卡片质感、动法和能用的动作都由这个包定死。
现在有 6 个：视频号花字 `shipinhao`、白菜暗调 `baicai`、Clean Finance `nischa`、贴纸讲解 `sticker`、杂志纸张 `vox`、字幕新闻 `caption_news`。
每个包的 `STYLE.md` 是它的说明书，`pack.json` 里有菜单（`effects`）、额度（`budget`）、适合什么（`fit`）、品牌能换哪几项（`brand`）。包的写法见 `../../library/packs/README.md`。

动效库（`../../library/talking-head/effects/`，151 个）**留着当零件**：包把它列进菜单，它就换上包的字体和颜色来用；没有包列它，一键成片就不会选到它（以后做手动剪辑时给人挑着用）。
没有合适的包时，告诉用户，或者照一个对标视频新建一个包（见下面「用户给了喜欢的例子」），不临时拼。

## 用户给了喜欢的例子 → 做成一个新包，再用它剪

用户说「照这个风格剪」并给了视频（链接或本地文件，最好 1–3 条同一个博主的），就把它变成一个风格包，以后谁都能用：
1. **拿到视频**：链接用 video-teardown skill 或 yt-dlp 下到 `../../library/packs/<新id>/ref/`；手机录屏要先找出真正的视频区域再裁（去掉 app 界面）。
2. **照着做包**：按 `../../library/packs/BUILD_BRIEF.md` 做——每 0.5–1 秒抽帧看清字体、字号、颜色、字幕、卡片、背景、动法，
   选最接近的免费可商用字体，写 `STYLE.md` + `pack.json`（菜单 / 额度 / fit / brand）+ `pack.css`，库里没有的招牌动作写进包的 `effects/`。
3. **先给用户看对比图**：用用户自己的素材（没有就用测试素材）出 4 张定格图，和原版上下并排（`frames/compare.jpg`）。用户说像、好看，才算包做好了。
4. **再按「一键成片」剪**：第 4 步直接用这个新包。用户提的意见改进包里（STYLE.md / pack.css / budget），下次自动生效。
同一个博主多给几条，包就更准；不同博主的风格不要混进一个包。

## 一键成片（默认）

用户给一条口播原片（可选：品牌链接、上传素材），不用逐步确认，像剪辑师一样**先看懂、再选包、再导演**，直接出片。
**包是菜单，不是清单**：包里有很多动作，一条片子只挑最需要的几个，同一种作用用同一个画面，其余时间留干净的人脸 + 字幕。太满、换太多、没有逻辑，比少一个效果更难看。

0. **只有照片 + 文稿时，先出数字人原片**：文稿放 `PROJECT/script.txt`，然后 `python3 scripts/avatar.py PROJECT --photo 照片.jpg [--voice Olivia] [--lang en]`。
   用的是**用户自己的 HeyGen**：有 API 密钥（用户自己存在 `~/.secrets/heygen.env` 或环境变量 `HEYGEN_API_KEY`，不在聊天里要）就自动生成 Avatar IV 视频并下载；
   没有密钥就打印网页上用套餐积分做的步骤，做好后 `--from-file 下载的.mp4` 接回来。照片用胸口以上的近景（脸大、口型更准）。出来先逐秒查假手和嘴型，有问题重生成。
1. **准备**：`python3 scripts/prep.py PROJECT [--lang en] [--brand https://品牌官网]`
   → 打印台词（一句一行：词编号 + 秒数）、品牌资料。有稿子先放 `PROJECT/script.txt`。
   然后 `python3 scripts/logos.py PROJECT`：找出稿子里提到的每个品牌，拿官方 logo（OFFICIAL 表 → 已核对的缓存 → 品牌自己的官网），
   出 `PROJECT/stills/logos_check.jpg`（每个 logo + 来源网址）。**打开看一眼**：needs_check 的人工核对（`--approve 名字`），not_found 的不放 logo、只出文字。
2. **看片**：抽 6–8 帧拼成一张看。记下：气质（平静 / 高能 / 专业）、**画面亮还是暗**、头顶有没有空位（上方图解板要用）、背景乱不乱、哪里有空位放图形。
3. **审稿（逻辑，必做，规则检查会查）**：在 `PROJECT/brief.md` 写「## 审稿」表，**稿子每一句一行**：
   `| 句子（词编号） | 这句在干什么（钩子/痛点/转折/产品/用法/证据/金句/号召…） | 观众此刻缺什么（看不懂？记不住？没感觉？什么都不缺） | 配不配 | 为什么 |`
   只有「观众缺东西」的句子才配；缺什么决定配什么：看不懂 → 图解/截图/界面，记不住 → 清单/大字/数字，没感觉 → 情绪/推近，什么都不缺 → 不配。
   最后**圈出全片最重要的 3–5 句**（钩子、产品出场、最关键的一个数或清单、结尾），大动作只给这几句。
4. **选包**：`python3 ../../tools/pick_pack.py PROJECT [--tone premium|lively|calm|friendly|punchy|editorial]`
   → 按四样打分推荐 2 个：**稿子内容**（有没有数字、清单、观点、情绪、产品出场）、**素材条件**（亮暗、头顶空间、背景）、**想要的调性**、**品牌官网的样子**。
   读这两个包的 `STYLE.md`（本质、「它不是什么」、句子 → 画面对照表），对照审稿表定一个。在 brief.md 写「## 视觉系统」：用哪个包、为什么、另一个为什么不选。
   用户指定了包就用指定的。选包参考：

   | 包 | 最适合 | 不适合 |
   |---|---|---|
   | 视频号花字 `shipinhao` | 种草、强情绪开头、轻松话题、短平快 | 严肃 B2B、数据多、要稳重高级的品牌 |
   | 白菜暗调 `baicai` | 观点、个人 IP、想显得高级的产品介绍 | 活泼搞笑、儿童类、大量图表 |
   | Clean Finance `nischa` | 讲数据、算账、产品原理、效率工具（需要头顶有空位放图解板） | 纯情绪、只有观点没有数和步骤 |
   | 贴纸讲解 `sticker` | 知识讲解、教程、列清单、亲切的产品介绍 | 要强冲击力的广告、快节奏促销 |
   | 杂志纸张 `vox` | 深度观点、品牌故事、有质感的讲解 | 快节奏促销、情绪化种草 |
   | 字幕新闻 `caption_news` | 资讯、数据快评、静音刷的场景 | 需要大量图解或贴纸氛围的内容 |

5. **选动作（从菜单里只挑几个）**：在 brief.md 写「## 动作」表：`| 作用（钩子/证据/清单/数字/结尾…） | 用包里哪个动作 | 用在哪几句 |`。
   规则（规则检查按包的 `budget` 查）：
   - 一条片子最多 `budget.moves` 种动作（每个包自己定：视频号花字最严，2–4 种；其他包按各自测试片的量放宽）；**同一种作用全片用同一个动作**（三个卖点都用同一种卡片，不要每次换花样）。
   - 背景最多 `budget.backgrounds` 种，**只在段落变化时换**，不为热闹换。
   - 大高光（超大字、整屏接管）最多 `budget.peaks` 个，只给第 3 步圈出来的句子，在 shots.json 里写 `"peak": true`。
   - 动作总时长不超过全片的 `budget.cover`，两个动作之间至少留 `budget.gap` 秒人脸。
   - 有的动作不适合这条视频就不用，包里有不等于要用。
6. **导演**：写 `PROJECT/shots.json`，第一行 `"pack": "<id>"`，每个镜头加 `"why"`。文字用原话，参数按这条视频调。故意打破间隔时写 `"why_break"`。
7. **检查**：`python3 scripts/check_plan.py PROJECT`，有 ✗ 就改到「通过」（有包时查：动作都在菜单里、种数 / 背景数 / 高光数 / 覆盖时长 / 间隔在额度内、同一作用有没有换画面、审稿每句都有、开头 3 秒有钩子）。
8. **自己回看挑刺**：`python3 scripts/render.py PROJECT --sheet 1`（每秒一帧）+ 每个动作出现后 0.5 秒的定格图，**逐条过「审美自查」**和包 `STYLE.md` 最后一节的常见错误。
   不合格就改，把改了什么记在 brief.md「## 自查时改过的」。
9. **出片**：`python3 scripts/render.py PROJECT` → `out.mp4` + `out_镜头清单.md`（渲染超过 10 分钟的命令时限时，放后台跑）。

- 原片放 `PROJECT/raw.mp4`。素材放 `PROJECT/uploads/截图|照片|B-roll视频|logo/`。**没传素材，需要素材的动效就不用**。
- **品牌**：给一个官网链接（`--brand`）就够了。官网的颜色、字体、logo、app 图标存进 theme.json 和 PROJECT/brand/。有包时品牌**只换强调色**（关键词色块、进度条、高亮、小标签），包的底色、纸张、字体体系不变；浅色品牌色做文字看不清时，引擎自动换成同色系的深色（≥4.5:1），色块仍用原色。包允许时（`brand.font: display`）标题换品牌字体。logo 只在开头 / 结尾（`"logo": true`），品牌名照官网写法。每个包能换哪几项写在它的 `pack.json` → `brand`。没给品牌就用包自己的颜色（不从画面取色）。
- 原片是 AI 数字人时，自查要逐段看手和嘴（会出假手、糊手），有问题就重生成原片，不要靠动效去盖。有 script.txt 时粗剪只剪 0.9 秒以上的长停顿、不跳景别——照稿念的换气常落在手势中间，剪了手会闪现。
- 有稿子（数字人的稿子、提词稿）就放 PROJECT/script.txt：字幕用稿子原文，不靠转写猜字。
- 用户说「先给我看看」时，第 6 步的定格图和简报先给用户看，确认了再出片。

## 审美（依据：research/one-click-aesthetics.md，CapCut / Captions / Submagic / OpusClip / Descript 的做法 + 设计规范）

一键工具出片好看，靠的不是效果多，而是**先锁一整套视觉系统，全片所有东西都从这一套里取**。我们照做：

1. **一套视觉系统 = 一个风格包**（第 4 步写进 brief.md）：字体、颜色、卡片质感都用包定死的，引擎会锁住全片字体；品牌只换强调色。
   不用带 ⚠固定色 的动效（它们的颜色跟不上品牌），除非颜色本身有意义（红叉、绿勾）。
2. **卡片跟着画面亮暗和品牌走**：亮画面（户外白天、白墙）或浅色品牌 → 实心白卡 + 深色字；暗画面 → 深色卡 / 毛玻璃 + 白字。
   毛玻璃放在亮背景上要够实（看得清字），对比度至少 4.5:1。全片卡片同一种质感，不混白卡、黑卡、纸片、霓虹。
3. **一个主风格**：效果只从主风格 + 「通用」里挑（看 `style` 标签）。高能网感片别混进电影感的慢光效，知识类片别混漫画贴纸。
4. **在内容转折处加东西**（换话题、举例、出数字、下结论、产品出场），不按固定间隔；没有转折的句子留干净人脸。
5. **同一时刻只变一样**：字幕高亮、卡片、推近不同时出现；上一个还没看完不上下一个。
6. **字少、字大、字是原话**：卡片里一行能读完（中文 ≤ 12 字、英文 ≤ 6 词），超过就拆或只留关键词。
7. **字和图形在安全区**：居中约 900×1400 内；底部字幕带、右侧 120px（平台按钮）不放重要东西；不压脸。
8. **品牌出场要像官网**：品牌名照官网写法和字体；结尾卡用 `"logo": true`；颜色用官网最显眼的那个（按钮 / logo 色），不是随便一个变量。
9. **克制 = 高级**：一条片子只用包里 3–4 种动作，同一种作用用同一个画面（一致才有逻辑），背景只在段落变化时换；宁可少一个，也不要多一个不确定的。

### 审美自查（第 8 步，每条都要过，过不了就改）
- [ ] 每张定格图：字一眼能读完吗？字和背景对比够吗（亮背景上的浅字、彩色背景上的彩字都不行）？
- [ ] 全片颜色数：除了画面本身，是不是只有主色 + 白/墨色（+ 有意义的红绿）？有没有出现品牌之外的颜色？
- [ ] 字体：所有字是不是同一个字体家族？品牌名写法对吗？
- [ ] 卡片：质感一致吗（都是白卡 / 都是玻璃）？圆角、阴影看起来是一家人吗？
- [ ] logo：每个 app / 品牌 logo 是官方正版吗？
- [ ] 位置：挡脸、压字幕、出安全区、和手或道具打架了吗？
- [ ] 节奏：有没有两样东西同时抢眼？有没有哪一刻空得太久或挤得太满？

## 怎么挑：护栏（依据：research/auto-edit-rules-draft.md，实测 21 条爆款 + 约 40 篇教程/工具做法）

1. **开头 3 秒**放一个钩子：钩子句里最关键的短语做大标题（用途「开场钩子」），停 3–5 秒。
2. **只给这几类句子配动效**，按优先级：数字 → 清单步骤 → 对比前后 → 定义概念 → 金句观点 → 引用证据 → 提到具体东西 → 结尾号召。普通叙述句不配；10–20 秒没有动效是正常的。
3. **按档位的上限放**（prep 会打印）：适中 = 每 10 秒最多 1 个小动效、每分钟最多 3 个大动效、挡脸 ≤ 15%。先放最值得的句子，放到上限就停。字幕样式、推近这类「底层」不算数。
4. **间隔**：两个动效至少隔 3 秒；两个大动效至少隔 8 秒，中间切回人脸。
5. **不重复**：同一个动效只用一次；同一组（`group`）只用一个。
6. **位置不打架**：看 `zone`，同一时间不放两个同位置的；图形不压字幕带。
7. **默认不加** emoji 贴纸和结尾「关注我」卡，用户要才加。
8. **字只用原话**：`fills` 里写「用原话」的参数，从这句话里摘，不改写意思、不编数字。界面示意（通知、聊天、草稿里的消息）可以写贴合原话意思的短句（她说「客户来催进度」→ 通知写「进度怎么样了？」），但不编事实和数字，并在简报里注明是示意。
9. **图标说什么给什么**：提到 app / 品牌 / 具体东西时，图标参数写那个词（如 `Slack`、`gym`），没有对应图标的那项自动不出。常用 app 一律出官方彩色 logo（scripts/icons.py 的 OFFICIAL 表，写死、核对过）；自查定格图时专门看 logo 对不对。其他品牌只用 logos.py 核对过（ok）的 logo；品牌永远不出单色简化图标、不手画、不猜——找不到就返回空，只出文字。
10. 一条视频只用 1 个强调色（theme.json），不在 shots.json 里另配颜色。

## 硬规则

1. 只出竖屏 1080×1920。
2. **每个动效都要和那句话直接相关**，别为了热闹乱套。
3. **图表里的数字只能来自原话或用户给的资料，不许编。**
4. **网上的图不直接用**，别人的肖像不要出现。品牌 logo 只在说到这个品牌时出现（图标库，见 `../../library/icons/`）。用户自己上传的截图、录屏可以用。

## 高亮怎么挑

`keywords` 管两件事：底部字幕里哪几个词变色，以及「关键词放大」弹出的大字。挑错了观众会看不懂，按下面的规则挑：

1. **只看高亮也要能看懂。** 高亮一整个短语（`"say no"`、`"too cold"`），不要两个拆开的词（❌ `["problem", "AI"]` → 观众看到 PROBLEM / AI 不知道在说什么）。
2. **挑信息量最大的地方**：转折、情绪词、数字、她的主张。不挑 problem、thing、way 这类空泛的词，也不挑人名打招呼。
3. **弹出的大字只放开场和结尾**（或全片最重要的一句），用原话里的短句，不改写意思。
4. **一句话最多一处高亮**，全片大概 5–8 秒一处。不是每个镜头都要写 `keywords`。
5. 写之前自问：**把高亮的词单独念出来，像不像这句话的标题？** 不像就换。

例子（work_example）：

| 原话 | ❌ | ✅ |
|---|---|---|
| Today's AI is powerful. But somehow… | `powerful` | `AI is powerful` |
| …repetitive, time-consuming, and emotionally draining… | `repetitive`、`draining` | `emotionally draining`（只留情绪最重的一处） |
| …sound thoughtful… say no without sounding too cold | `thoughtful`、`no`、`cold` | `sound thoughtful`、`say no`、`too cold` |
| …the kind of problem AI should be solving | `problem`、`AI` | `AI should be solving` |

## 不满意某个镜头怎么换

出片时会生成 `out_镜头清单.md`，每个镜头后面列了 2–3 个可以换的动效（同一种句子用途优先，不够再补同类别的）。
把 `shots.json` 里那行的 `template` 改掉、按新模板的 `meta.json` 补参数，再出片。
也可以 `python3 ../../tools/catalog.py --alt 模板id` 直接查，或在库页面里按「句子用途」筛选。

## 分步流程（要逐步确认、或单独重跑某一步时）

| 步骤 | 做什么 | 命令 / 产出 | 用户确认 |
|---|---|---|---|
| 0 | 建项目文件夹，原片放成 `PROJECT/raw.mp4`（只用一段就先截出来） | `ffmpeg -ss 起点 -t 时长 -i 原片 raw.mp4` | — |

### shots.json 格式

```json
{
  "skin": "clean",
  "shots": [
    {"words": "0-9",   "purpose": "开场钩子", "template": "keyword_pop",   "params": {"keywords": ["AI is powerful"]}},
    {"words": "16-24", "purpose": "金句观点",   "template": "text_sandwich", "params": {"text": "DRAINING"}},
    {"words": "31-41", "purpose": "引用证据", "template": "doc_fly",       "params": {"images": ["assets/docs/gmail.jpg", "assets/docs/chat.jpg"]}}
  ]
}
```

- `words`：`work/transcript.txt` 里的词编号范围，模板从第一个词开始、到最后一个词结束。没写到的词就是普通露脸段落，只有字幕。
- `purpose`：这句话在做什么，取值见 `tags.json` 的 `purpose`（开场钩子 / 数字 / 清单步骤 / 引用证据 / 金句观点……）。先判断用途，再从库里挑这个用途下的动效；镜头清单里的「可以换成」也按它推荐。
- `params`：每个模板要什么写在库里它的 `meta.json` 里。
- `keywords` 里的词在底部字幕里也会高亮。
- `focus`（可选）：`[x, y]`，脸在画面里的位置（0–1）。不写就从抠像里自动算。
- `skin`：`clean`（克制，深色加荧光绿）或 `pop`（网感，亮黄加蓝）。
- 素材（B-roll、截图）放 `PROJECT/assets/`。视频类 B-roll 先拆成帧：`ffmpeg -ss 起点 -t 时长 -i 视频 -q:v 3 assets/名字/%06d.jpg`，参数写 `{"frames": "assets/名字", "fps": 30, "count": 帧数}`。

## 加新模板

1. 新建 `library/talking-head/effects/<id>/`，写 `meta.json`（标签按 `tags.json`：句子用途、分量、挡脸、位置、组、前提、素材、类别；再加 `use_for`、`duration`、`fills`、参数、出处）和 `template.js`（`setup` 搭画面，`frame` 每帧按时间改样式）。照现有模板的写法，只用 `engine.html` 里的皮肤变量（`--accent` 等），换皮肤才会跟着变。
2. 在 `demo_rumi/shots_*.json` 里用一次，跑 `python3 tools/previews.py <id>` 出预览，再跑 `python3 tools/catalog.py` 更新总表和库页面（标签写错会报错）。

## 环境

- python3：`openai-whisper`、`playwright`（带 Chromium）、`pillow`、`numpy`；ffmpeg。
- 抠像用 macOS 自带的 Vision 人像分割，不下载模型、不上传。第一次编译：
  `swiftc -O scripts/matte.swift -o scripts/matte`
  如果报 `redefinition of module 'SwiftBridging'`（Command Line Tools 自带的问题），用 vfsoverlay 把 `bridging.modulemap` 换成空文件再编译。
- 不在 Mac 上时没有 Vision，抠像要换别的工具（还没做）。
